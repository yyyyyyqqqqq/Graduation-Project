# 5–8 分钟答辩演示

准备：解压完整交付候选，选择新的绝对路径作为 `--data-dir`，打开本脚本及
`evidence/sample-report/current-finding-report.html`。样例报告是部署 app 生成的历史快照，
其采集时间和 provenance 在相邻 manifest 中；不要编辑 HTML 或重写 fetchedAt。
先按 [用户手册](USER-MANUAL.md) 启动。

| 时间 | 操作与讲解 |
| --- | --- |
| 0:00–0:40 | 启动，说明本科项目范围；创建“合成答辩项目”，展示概览只跟随当前项目。 |
| 0:40–1:50 | 导入 `demo/defense-sbom.json`；查看 3 个普通组件和质量诊断；解释 Preview 不持久化，然后显式 Apply。 |
| 1:50–2:40 | 查看当前组件、根组件和依赖页；展示 root→lodash→helper 的声明路径；强调不是 runtime reachability。 |
| 2:40–3:20 | 漏洞页选择 lodash：展示 Identity/Candidate/Applicability/Finding 的分工。网络可用时才走正常查询确认；失败不解释为无漏洞。 |
| 3:20–5:20 | 打开离线“方法验证”，展示 40 真实样本、54 合成用例、三阈值分布；选样本展示 Priority、Support、Driver、Why、关键证据和边界。说明实验阈值不会修改生产 0.90。 |
| 5:20–6:20 | 在浏览器打开随包静态样例报告，展示单 Finding、三个时间锚点、版本和证据来源；说明不是项目级报告。 |
| 6:20–7:00 | 陈述 PyPI/npm 子集、Unknown、数据不持久化、证据支持不等于预测置信度等限制。 |

## 离线主路线

Foundation、Validation、Presentation 和随包 HTML 均不依赖外部 provider。
方法验证直接使用内嵌冻结输入；不启动在线采集工具，不改系统网络、DNS或代理。
跳过在线查询演示，用方法验证样本和静态报告解释漏洞与证据链。
不要承诺离线现场一定能重新生成 Fresh Finding 报告；历史缓存可能 Stale 或缺失。
冷启动无缓存时也应能完成上述离线核心答辩。

## 用户保留验收

用户本人可在候选包上按上表走完一遍，并检查：窗口/滚动/原生文件框可用；
创建、导入、Apply、重启保持正确；方法验证无需网络；HTML 可打开且无脚本执行。
任一业务错误、崩溃、数据串项目或报告来源不明即不通过，并保留原始证据。
记录实际时间、操作人、结果，不把 Codex/自动测试写成用户操作。
有另一台无开发环境 Windows 时可补验；没有则按非阻塞未验证记录，不强制要求。
